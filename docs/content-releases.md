# Classified content snapshots and release selection

The app loads the pinned public content revision at startup. `ContentSnapshotLoader` parses Markdig sections deterministically, validates all pages before use, and builds an immutable snapshot with the site identity, sections, documents, and a content hash. Unknown section headings become `generic`; a document may set `sectionType` in front matter to override classification. `ContentSnapshotLoader.Compare` produces a structural document/section diff. No AI participates in validation or publishing.

Runtime selection is disabled unless both `Content__ReleasesRoot` and `Content__ActivationToken` are configured. Each child folder under the release root is a named release with `site.json` and `pages/`, produced from a reviewed public content commit. Send a POST to `/internal/content/preview/{releaseId}` with `X-Content-Activation-Token` over HTTPS to validate and inspect the diff without switching. After review, POST `/internal/content/activate/{releaseId}` with the same header. Invalid candidates leave the current snapshot active. Re-activating a previous release ID rolls back content atomically. Keep the token secret and restrict filesystem access to the release root. Public draft previews are intentionally unavailable because the content repository is public; draft content remains excluded from routes and indexing.

Each request pins one snapshot before routing, so page content, site identity, canonical/social metadata, and sitemap paths agree during activation. Structured data remains disabled pending owner approval. Styles and script entrypoints carry the content version; HTTP responses use `no-cache` so imported scripts and other static assets revalidate across app releases. The content release root is separate from the IIS application release directory; staging rollback of an app release still follows the IIS runbook.
