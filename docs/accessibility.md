# Accessibility and responsive quality checks

`npm run test:a11y` builds the client bundle and checks the published page templates in Chromium, Firefox, and WebKit. It checks for horizontal overflow at 320, 360, 768, and 1440 CSS pixels, then at 720 CSS pixels to cover the content width produced by 200% zoom on a 1440-pixel desktop viewport, and with 200% root text size at 1024 CSS pixels (WCAG 1.4.4). Text enlarged to 200% on a 320-pixel viewport corresponds to roughly 800% zoom and is outside the WCAG AA reflow requirement, so it is not tested. Chromium runs axe-core against WCAG 2.0, 2.1, and 2.2 A/AA rules in both themes and fails for critical or serious violations. It also checks the theme toggle in both themes, that the easter egg is hidden by default and appears only through the secret triggers (keyboard sequence and logo clicks), the CV table of contents, the floating CV search panel, the `/search` redirect, that the CV hero, figures, git log, assignment cards, and skill chips are present without JavaScript, that the decorative background canvas is `aria-hidden` and stays static under reduced motion, that the header, cards, role chips, the sticky table of contents, and free-standing CV text sit on opaque surfaces in both themes at 375 and 1440 CSS pixels, and that the constellation reacts to hovering an assignment without console errors. Constellation layout is unit tested to keep nodes and labels inside the safe area. The constellation moves behind the copy at every width, and axe cannot measure text over canvas pixels. For that reason all cards and sticky bars are opaque, the canvas is clipped to start below the sticky menu (or sticky table of contents), the footer is transparent (its text is a measured obstacle for the nodes), and headings, paragraphs, and lists outside cards get a soft page-coloured surface; the surface list mirrors `SURFACE_SELECTOR` in `constellation-engine.ts`. A heading's surface only hugs its words so the constellation stays visible in the empty space beside it, while the section rule above an h2 still spans the column; the test checks both at 1440 CSS pixels. Technology labels remain visible at every width (11 px below 700 CSS px, 13 px otherwise), and the number of individually shown technologies scales with usable area. The remaining technologies are represented by a floating Övrigt bubble; assignment, hover, pin, and search matches can pop the most relevant hidden names out of it. The bubble ignores the cursor. Clicking reveals usage-ranked batches of three, rotating the oldest batch when the collision-derived orbit capacity is full; popped labels orbit outward from the bubble without overlapping drawn labels. A four-second inactivity timer resets after each click; then items return newest first in a 150 ms stagger, with the bubble count restored as each arrives. Highlighted items remain out until their highlight ends. Paused and reduced-motion states snap the collapse. The `+fler` marker is plain text and the decorative canvas has no navigation or keyboard target. Unit tests cover the responsive label rule, visibility ranking, category representation, pop-out ranking, and intro easing. Contrast audits wait for entrance animations and transitions to finish so mid-animation colours are not measured.

## Manual release checklist

- Navigate every page with Tab, Shift+Tab, Enter, and Space; confirm the skip link appears first, focus remains visible, and there is no trap.
- Check the primary flow with NVDA + Firefox or VoiceOver + Safari, including headings, navigation landmark, page language, link names, and contact path.
- Check current stable Chrome, Firefox, Edge, Safari, mobile Chrome, and mobile Safari at 320, 360, 768, and 1440 CSS pixels and 200% zoom. Record browser versions and results in release notes.
- Check color contrast in each theme and confirm reduced-motion preferences are respected after themes are enabled.
- The browser suite checks both Christmas and New Year calendar layers in light and dark mode under reduced motion. Their decorative border tokens do not alter foreground/background contrast.
- Review lab performance measurements for each release. Record LCP, CLS, and INP when field data is available.
- Verify TLS and security headers in the deployed environment; these depend on the approved IIS/reverse-proxy configuration.

The CI workflow also audits npm and NuGet dependencies and scans repository files for secrets. Production security headers and TLS are deployment checks because the deployment environment is not yet configured.

The web host sends a restrictive Content Security Policy, `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy`. It suppresses the Kestrel server header. HSTS is sent only when the application is in Production, the approved `siteUrl` uses HTTPS, and the incoming request is HTTPS. TLS termination and trusted proxy configuration must be verified in IIS before release.

## Constellation and skill groups

The `#constellation-field` canvas is decorative and marked `aria-hidden="true"`. The skill groups and technologies it draws are server-rendered as a full semantic equivalent on `/services` and `/cv`, derived from the same CV data as the canvas. Each group name is a toggle button that highlights the whole group; each technology is a toggle button for a single technology. Only one pin is active at a time, `aria-pressed` reflects it, Escape clears it, and a `role="status"` region announces what is highlighted. `/services` explains the map in visible text: dots are technologies and lines connect technologies used in the same assignment.

Visible constellation nodes are ranked by assignment usage, with a representative from each category when the category count is at most half the visible budget. The remainder is consolidated into one floating Övrigt bubble, which ignores the cursor; clicking reveals the next three hidden technologies by usage, and hidden-edge links follow the bubble. A four-second inactivity timer resets after each click, then popped technologies return newest first in a 150 ms stagger. Highlighted items remain out until their highlight ends; paused and reduced-motion states snap the collapse. The canvas remains decorative and has no navigation or keyboard target.

The header has a pause button for the background animation (WCAG 2.2.2). The choice is stored in `localStorage` (`constellation-motion`). Without a stored choice the animation is paused below 700 CSS px and runs on wider screens. Under `prefers-reduced-motion: reduce` the animation never runs and the button is hidden. While paused, hover, focus and pins still update the static map. The first-layout cluster intro plays once even when the narrow-screen default is paused, then stops; reduced motion goes directly to the final layout. On narrow screens the group and technology buttons are at least 44 CSS px tall.
