# Accessibility and responsive quality checks

`npm run test:a11y` builds the client bundle and checks the published page templates in Chromium, Firefox, and WebKit. It checks for horizontal overflow at 320, 360, 768, and 1440 CSS pixels, then at 720 CSS pixels to cover the content width produced by 200% zoom on a 1440-pixel desktop viewport, and with 200% root text size at 1024 CSS pixels (WCAG 1.4.4). Text enlarged to 200% on a 320-pixel viewport corresponds to roughly 800% zoom and is outside the WCAG AA reflow requirement, so it is not tested. Chromium runs axe-core against WCAG 2.0, 2.1, and 2.2 A/AA rules in both themes and fails for critical or serious violations. It also checks the theme toggle in both themes, that the easter egg is hidden by default and appears only through the secret triggers (keyboard sequence and logo clicks), the CV table of contents, the floating CV search panel, the `/search` redirect, that the CV hero, figures, git log, assignment cards, and skill chips are present without JavaScript, that the decorative background canvas is `aria-hidden` and stays static under reduced motion, that the header, cards, role chips, the sticky table of contents, and free-standing CV text sit on opaque surfaces in both themes at 375 and 1440 CSS pixels, and that the constellation reacts to hovering an assignment without console errors. Constellation layout is unit tested to keep nodes and labels inside the safe area. The constellation moves behind the copy at every width, and axe cannot measure text over canvas pixels. For that reason all cards and sticky bars are opaque, and headings, paragraphs, and lists outside cards get a soft page-coloured surface; the surface list mirrors `SURFACE_SELECTOR` in `constellation-engine.ts`. Below 700 CSS pixels the constellation has no room beside the text, so it draws no technology labels and the canvas is subdued; a unit test covers that threshold. Contrast audits wait for entrance animations and transitions to finish so mid-animation colours are not measured.

## Manual release checklist

- Navigate every page with Tab, Shift+Tab, Enter, and Space; confirm the skip link appears first, focus remains visible, and there is no trap.
- Check the primary flow with NVDA + Firefox or VoiceOver + Safari, including headings, navigation landmark, page language, link names, and contact path.
- Check current stable Chrome, Firefox, Edge, Safari, mobile Chrome, and mobile Safari at 320, 360, 768, and 1440 CSS pixels and 200% zoom. Record browser versions and results in release notes.
- Check color contrast in each theme and confirm reduced-motion preferences are respected after themes are enabled.
- The browser suite checks both Christmas and New Year calendar layers in light and dark mode under reduced motion. Their decorative border tokens do not alter foreground/background contrast.
- Review lab performance measurements for each release. Record LCP, CLS, and INP when field data is available.
- Verify TLS and security headers in the deployed environment; these depend on the approved IIS/reverse-proxy configuration.

The CI workflow also audits npm and NuGet dependencies and scans repository files for secrets. Production security headers and TLS are deployment checks because the deployment environment is not yet configured.

The web host sends a restrictive Content Security Policy, `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy`. It suppresses the Kestrel server header. HSTS is sent only when the application is in Production, the approved `siteUrl` uses HTTPS, and the incoming request is HTTPS. TLS termination and trusted proxy configuration must be verified in IIS before release.
