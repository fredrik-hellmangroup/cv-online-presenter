# Architecture

The application is a single deployable ASP.NET Core Blazor Web App using Static SSR for public pages, with explicit module projects. Browser behavior is progressive TypeScript built independently into static assets; no interactive Blazor render mode is enabled. Pages remain readable without JavaScript.

| Project | Responsibility | Allowed dependencies |
| --- | --- | --- |
| `Portfolio.Contracts` | Stable interfaces and cross-module value types | None |
| `Portfolio.Content` | Markdown loading, content schemas, and validation | Contracts |
| `Portfolio.Experience` | Visitor-facing use cases and presentation models | Contracts, Content |
| `Portfolio.Publishing` | Publication selection and release composition | Contracts, Content |
| `Portfolio.Infrastructure` | Host-specific adapters | Contracts |
| `Portfolio.Web` | HTTP composition, routes, and dependency injection | All modules |

Dependencies point inward to contracts and content capabilities. Module projects do not depend on Web or on each other in a cycle. The Web host is the composition root. The client build has no dependency on server modules.

The solution and client toolchain are pinned/documented so the same commands work locally and in CI.

The optional browser experience is composed from separate `ConstellationEngine`, `ThemeEngine`, `EasterEggEngine`, `CvTocEngine`, `CvSearchEngine`, `CountUpEngine`, and `CardGlowEngine` contracts in `client/src/experience.ts`. A failed engine is logged and does not stop the others. `client/src/experience-manifest.ts` declares the hidden easter egg triggers (five clicks on the logo mark, or the key sequence K-O-D; see [easter-eggs.md](easter-eggs.md)) and local calendar rules for Christmas (24–26 December) and New Year (31 December–1 January). No birthday date has been approved, so no birthday rule is shipped. Calendar layers set only a decorative border token; content, links, and navigation do not depend on them.

The CV page (`/cv`) is presented by `CvPresenter` in `Portfolio.Content`, which turns the sanitized HTML of the CV Markdown into a hero, figures, assignment cards with technology tags, skill chips, and the data for a `git log --graph` style timeline; see [cv-structure.md](cv-structure.md). A page that does not follow the expected structure falls back to plain Markdown rendering. The table of contents is built in the browser from the heading anchors that the Markdown pipeline generates (Markdig auto identifiers; the sanitizer allows `id`). Search is a floating panel on the CV page that calls `/api/search`; there is no standalone search page, and `/search` redirects permanently to `/cv`. Without JavaScript the CV stays fully readable; the table of contents, search panel, background, counters, and easter egg are progressive enhancements.

The design system uses Tailwind CSS v4 utilities built from `client/src/utilities.css`, semantic color tokens, custom Razor components, and separate Markdown typography in `site.css`. The dark, immersive direction uses a bundled open-licence condensed display font (Barlow Condensed, SIL OFL, `wwwroot/fonts`), system body text, and an orange accent. The background is a single decorative, `aria-hidden`, same-origin canvas: `ConstellationEngine` draws the CV's key technologies as a constellation. Technologies used together in at least two assignments are linked, the technologies of the assignment being read, hovered, or searched light up, and small data packets travel along the links. Nodes and labels are laid out inside a safe area (clear of the sticky header or table of contents at the top, the side edges, and the floating search button at the bottom) by the pure `placeNodes` function, which is unit tested at desktop and phone sizes. The canvas is capped in resolution, pauses when the tab is hidden, and draws one static frame under `prefers-reduced-motion`. Dark is the default theme; light is an alternative stored in `localStorage`. Tailwind output is compiled during `npm run build` and loaded as a versioned static asset. Theme and calendar layers preserve the same text and link tokens; reduced-motion CSS applies across all layers. This implements ADR-004 and ADR-006 (Immersive Dark, which replaces Scandinavian Editorial) without external font or image requests at runtime, and the CSP is unchanged.

`npm run check:architecture` checks the project-reference allowlist, cycles, and leftover `Class1` placeholders in CI. The Web host remains the only composition root. `Portfolio.Contracts` defines publication policy; `Portfolio.Publishing` implements it. `Portfolio.Experience` owns the core route map and the contact submission rules (`ContactSubmissionService`), and `Portfolio.Infrastructure` supplies the host clock adapter plus the Turnstile and SMTP adapters behind the `ICaptchaVerifier` and `IContactSender` contracts. Deeper experience composition and content-source adapters are deferred until the classified snapshot and discovery slices (#26–#27); these modules must not acquire outward dependencies in the meantime.

The contact page offers a Static SSR form protected by Cloudflare Turnstile only when Turnstile and SMTP are configured; otherwise it shows a `mailto:` contact card. The CSP is extended with `challenges.cloudflare.com` for `/contact` alone and only while the form is enabled. See [contact-form.md](contact-form.md).
